# 邮箱认证

## 使用方式

- `/sign-in`、`/zh/sign-in`：使用 Google 或邮箱密码登录；页面中切换注册、忘记密码。
- `?mode=register` 或 `?mode=reset` 可直接打开对应模式；`redirect` 仍只允许本站路径。
- 邮箱密码注册只需邮箱和非空密码，不限制密码字符长度，不发送验证码，也不验证用户是否能访问该邮箱。邮箱会去首尾空格并转小写；同一规范化邮箱不能重复注册。
- 注册时若该邮箱已经属于 Google 或其他账户，不会把密码绑定到该账户；请使用该账户原有的登录方式。邮箱密码登录与 Google 登录复用用户 ID、积分、订单和视频。
- 邮箱真实性未经确认的账户不会获得注册赠送积分或邀请奖励。找回密码仍需通过邮件验证码，用户必须能访问注册邮箱；无法收信时可以继续使用当前密码登录，但不能通过邮件重置。

## 本地开发

1. 执行 `npm run db:migrate:local` 应用数据库迁移。
2. `.dev.vars` 的 `SESSION_SECRET` 必须是至少 32 字符的随机密钥。
3. 邮箱密码注册及登录不需要发件配置。找回密码流程需配置邮件服务；本机回环访问可显示仅供本地调试的验证码。
4. 原来的开发者免密码登录放在折叠区，仍仅允许本机直连，禁止代理和生产环境使用。

调试验证码只由与原开发登录相同的本地请求判定允许。生产、预发和代理访问均不返回验证码。

## 正式环境

- 部署前执行 `npm run db:migrate:remote`；迁移仅允许 `verified_at` 为空，保留现有已验证账户的原值。
- 配置真实 `EMAIL_FROM` 和 Cloudflare Email Service 的 `EMAIL` binding，完成发件域验证；这些配置用于密码找回和交易邮件，不是新注册的前置条件。
- Google 登录按原有 `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET` 配置；可选，不影响邮箱密码注册/登录。
- 找回验证码邮件直接发送，避免明文进入发件箱、后台导出或重试队列；发送失败返回通用错误。邮箱服务未配置时，邮箱密码注册和已有账户密码登录仍可用。

## 认证与账户约束

- 注册和登录要求 `SESSION_SECRET` 是稳定且至少 32 字符的强随机值。邮箱格式仅做结构校验，不验证域名或收件能力。
- 密码使用随机 16 字节盐、PBKDF2-SHA512（100000 次）与以 `SESSION_SECRET` 为密钥的前置 HMAC。Workers 单次 PBKDF2 上限参见 [Cloudflare Workerd issue](https://github.com/cloudflare/workerd/issues/1346)。数据库只保存带版本的派生值。
- 密码找回验证码用途隔离，10 分钟有效、一次性使用、最多尝试 5 次；仅持久化 HMAC。相同邮箱发送冷却 60 秒、每小时最多 5 次；登录每邮箱 15 分钟最多 10 次尝试，成功后清除计数，同时保留请求 IP 限流。
- 邮箱注册仅能创建新用户，不得把未验证邮箱绑定到已存在的 Google 账户；数据库唯一索引负责并发去重。若先注册未验证邮箱，之后该邮箱所有者通过 Google 登录，系统会清除该未验证账户的密码凭据和旧会话，再绑定已经由 Google 验证的身份。
- 未验证邮箱注册不发放注册赠分或邀请奖励，也不授予基于邮箱名单的管理员角色。密码登录不会改变这一状态。之后通过 Google 或密码找回验证码证明同一邮箱时，才按站点配置授予角色并复用账户。
- 重置密码要求成功收取邮箱验证码，重置后撤销原有全部会话；注销账户时删除密码凭据、验证码及邮箱限流记录。
- `SESSION_SECRET` 同时参与密码 pepper，轮换后原密码不可校验。更换前需制定迁移或重置计划。
- 迁移新增 `lower(trim(email))` 唯一索引。若历史数据存在仅大小写/首尾空格不同的多条账户，迁移会失败，需人工确认账户和账务归属。
