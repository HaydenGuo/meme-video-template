# 邮箱认证

## 使用方式

- `/sign-in`、`/zh/sign-in`：Google 或邮箱密码登录；页面中切换注册、忘记密码。
- `?mode=register` 或 `?mode=reset` 可直接打开对应模式；`redirect` 仍只允许本站路径。
- 邮箱不限 Google：普通邮箱先收验证码，再设置 10–128 字符密码。
- 同一邮箱统一去首尾空格、转小写，数据库索引禁止重复。普通邮箱与 Google 登录都复用 `users.id`；积分、订单和视频继续绑定此 ID。
- 已有 Google 账户的邮箱经过验证码验证后可以设置密码；已有密码的邮箱再次注册不会覆盖密码，需使用登录或忘记密码。

## 本地开发

1. 执行 `npm run db:migrate:local` 应用 `0016_email_auth.sql`。
2. `.dev.vars` 的 `SESSION_SECRET` 必须是至少 32 字符的随机密钥。
3. 在本机回环地址打开注册页，发送验证码后页面显示“仅本地开发”验证码，不实际发送邮件。
4. 原来的开发者免密码登录放在折叠区，仍仅允许本机直连，禁止代理和生产环境使用。

调试验证码只由与原开发登录相同的本地请求判定允许。生产、预发和代理访问均不返回验证码。

## 正式环境

- 部署前执行 `npm run db:migrate:remote`；本次只应用了本地迁移。
- 配置真实 `EMAIL_FROM` 和 Cloudflare Email Service 的 `EMAIL` binding，完成发件域验证；普通邮箱注册和密码找回依赖真实收信。
- Google 登录按原有 `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET` 配置；可选，不影响已有邮箱密码登录。
- 验证码邮件直接发送，避免明文进入发件箱、后台导出或重试队列；发送失败返回通用错误。邮箱服务未配置时，已有账户仍可使用密码登录。

## 认证与积分约束

- 注册验证码和密码重置验证码用途隔离，10 分钟有效、一次性使用、最多尝试 5 次；仅持久化 HMAC。
- 相同邮箱发送冷却 60 秒，每小时最多 5 次；登录每邮箱 15 分钟最多 10 次尝试，成功后清除计数，同时保留请求 IP 限流。
- 密码使用随机 16 字节盐、PBKDF2-SHA512（100000 次）与以 `SESSION_SECRET` 为密钥的前置 HMAC。迭代次数适配 [Workers PBKDF2 限制](https://github.com/cloudflare/workerd/issues/1346)。数据库仅保存带版本的派生值。
- `SESSION_SECRET` 同时参与密码 pepper：必须稳定保管。更换后原密码派生值将无法校验，需要用户验证邮箱后重置密码；这不是透明轮换流程。
- 重置密码后撤销原有全部会话；注销账户时删除密码凭据、验证码及邮箱限流记录。
- 注册发放积分仍经原有账务事务和幂等键。注册并发冲突回滚后复用已创建账户，不重复发放。
- 迁移新增 `lower(trim(email))` 唯一索引。若历史数据中存在仅大小写/首尾空格不同的多条账户，迁移会拒绝执行；需先人工确认归属和账务合并，不能自动删除账户。
