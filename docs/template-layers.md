# 模板三层边界

模板与派生站共用一套代码基线。派生站差异只进入配置层或内容层，架构层能力由模板统一维护并通过 Git 合并传播。

| 层 | 主要位置 | 内容 | 同步模板更新时 |
| --- | --- | --- | --- |
| 架构层 | `src/routes/`、`src/server/`、`src/components/`、`migrations/`、构建/测试配置、`public/_headers` | 应用行为、服务端能力、数据结构、共享安全与质量规则 | 采用模板版本；若派生站曾改动，先停下确认并把通用修复回送模板 |
| 配置层 | `src/config/site.ts`、`wrangler.jsonc`、`bridge-site.json`、`package.json` 的 `name` | 品牌、功能参数、服务绑定、站点部署标识 | 保留本站取值，同时合入模板新增字段和默认结构 |
| 内容层 | `src/content/`、`public/`、`seed/` | 多语言页面文案、文章、品牌/展示素材、生成参考视频 | 保留本站内容并审阅结构变化；文案键与类型定义需跟随模板 |

## 边界规则

- 页面与 API 行为属于架构层；不要为了一个站点在共享路由或服务端代码里硬编码站点判断。
- `site.ts` 只表达结构化站点数据和功能参数；可见段落、标题与文章正文进入对应 locale 的内容模块。
- 内容层允许使用配置字段插值，但事实性内容应来自可核实资料；空素材不伪装成真实案例。
- `public/_headers` 虽在素材目录中，内容是共享安全策略，按架构层同步。
- `package-lock.json`、模板派生站删去的配置文件由同步脚本作为特殊项处理，不归入普通站点差异。

新增或移动站点差异文件时，保持 `AGENTS.md`、`scripts/sync-plan.mjs`、`tests/unit/sync-plan.test.ts` 和 `.claude/skills/new-hot-site/SKILL.md` 的分类一致。

## 初始化后检查

- 初始化结果中的站点身份与服务参数只写进配置层。
- 页面、指南和政策文案只写进内容层，并确认启用的每种语言都具有对应内容。
- 初始化工具不得修改架构层文件；共享行为变更应回到模板维护。
