# 固定参考视频复刻流程

每个梗先分析参考片、确定提示词并人工确认样片，再锁定模板。日常任务只接收人物图片、允许的时长和横竖比例；不需要 Hypit Runtime，也不需要每次调用语言模型重新分析提示词。

站点资料支持 `durations`（三个递增整数，4–15 秒）、`aspectRatio`，以及 `workflow: { "type": "reference-remix-v1", "cutFrames": [0, 81, 129, 183, 306, 396] }`。cutFrames 使用 30fps，按实际参考片填写，不同梗不能照搬镜头边界。默认仍为 5/12/15 秒；14 秒素材应显式设置 5/12/14。

初始化生成的 `bridge-site.json` 含固定提示词、工程参数及每档参考片 SHA-256。上线或更换参考片后，必须通过 Bridge 更新脚本应用完整片段；只上传 R2 或只更新哈希都不算完成。站点声明必需的 `reference-remix-v1`，Bridge 在创建任务记录前核对工作流，缺配置会拒绝请求，避免静默使用旧流程。更换参考片需重新审阅模板并更新哈希，不能只替换 R2 文件。不要将男性样片中的服装描述写进通用人物提示词；人物身份和服装由用户图片提供。

## 自动任务

1. 网站沿用现有登录、积分预扣、队列和失败退款逻辑。
2. Bridge 下载白名单媒体，校验参考片哈希、时长、音轨及图片是否可解码。
3. Bridge 抽取原视频音轨，生成无声动作参考视频；人物参考图、静音视频、时长/比例和模板固定提示词直接提交给 NoToken API。
4. NoToken 异步生成一个连续表演视频；Bridge 轮询任务，不因状态查询暂时失败而重提生成请求。
5. Bridge 将生成画面与提取出的原声音轨合成，检查成品文件大小、画幅、时长及视频/音频轨道后交付。检查不保证人物相似度、动作质量或听感，需要人工抽查。

Bridge 轮询原 NoToken 任务，服务重启后继续查询；提交回执不确定时保留 `attention` 占位，禁止盲目再次付费。参数解析或本地 Source 检查明确失败且尚未进入提交边界时，任务才会直接失败；服务商明确拒绝时网站走已有退款路径。服务商限流、余额、任务时限和账号权限需单独核验。

## 并发

Bridge 默认最多维护 8 个远程模型任务、100 个排队任务；VPS 本地 FFmpeg/FFprobe 同时最多处理 2 项。模型并发值可配置，受服务商 API 限流、账号权益和带宽约束；提升队列数字本身不会让服务商接受更多请求。较低的本地媒体并发可避免 2 vCPU VPS 同时转码过载。

## Hypit 兼容回退

如运维者显式配置 `engine=hypit`，Bridge 才调用 Hypit Runner；该分支需要额外安装 Hypit Runtime、Provider 凭据和固定工程。直接 NoToken 路径为默认值，健康接口中的 `engine` 字段标识实际 Runner；兼容 Worker 的 `mode=hypit` 字段不代表 Hypit Runtime 正在运行。

## attention 恢复

恢复操作必须先停止 Bridge。旧 Hypit 任务恢复命令只适用于明确使用 Hypit Runner 创建的 Build；NoToken 任务必须用 Bridge 中已有的远程 task id/status 查询流程继续处理，不能把 NoToken ID 交给 Hypit CLI。提交状态无法确认时不得重新提交同一任务，以免重复消耗额度。
