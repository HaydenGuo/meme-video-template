# 模板上站效率优化

目标是从一份梗资料与素材建立独立站点，按阶段接通登录、生成和充值。每站独立账户、积分、会话密钥和 Cloudflare 资源；可复用的是服务配置来源与共用 Bridge；Bridge 默认直接调用 NoToken，Hypit Runtime 仅作显式兼容回退。

## 已实现：分阶段开放

- 初始化资料的 `launch` 选择 `local / showcase / accounts / generate / full`。
- `npm run site:mode -- <阶段>` 默认预览，`--apply` 仅修改本地开关，不部署、不修改密钥。
- 页面与 API 共用开放状态；新购买关闭时仍处理历史订单和订阅，新生成关闭时仍处理已有任务。
- doctor 只要求已开放功能需要的服务商配置，检查开关拼写；生产仍禁止开启 mock 功能。
- `SHOWCASE_MODE` 保留为新站仅展示模式，不应用于有活跃任务和订单的站点。

用法见 [初始化](site-initialization.md)、[环境配置](env.md) 和 [GitHub 自动部署](cloudflare-auto-deploy.md)。本批不创建云资源、不修改 VPS，也不切换现有站点的功能状态。

## 下一批：可恢复的云资源初始化

1. 从站点配置读取明确账户、Worker、D1、KV、R2 和 Queue 名称，默认只预览。
2. 查询现有资源后创建缺失项，核对资源身份后回填 ID；重复运行复用本站资源，不重置数据库或余额。
3. 迁移和上传素材逐步记录结果，失败后从未完成步骤继续；不因超时盲目重复外部创建。
4. 密钥从 Infisical 的名称映射读取并直接写入 Worker；不进入配置文件、Git 或报告。
5. 部署串起现有成功 CI 和确切 SHA 检出，输出公网地址与尚未接通项。域名委派和 Google 回调登记单独记录状态。
